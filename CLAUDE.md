# Зубрик: Telegram-бот и Mini App для учеников курса

Учитель (Telegram ID `7183098167`, задаётся в `ADMIN_IDS`) создаёт группы, добавляет туда учеников и отправляет им тесты. Ученики решают тесты в Mini App в стиле Duolingo и смотрят статистику на диаграммах.

## Главная задача Claude в этом репо: конспект → тест

Когда учитель присылает конспект урока:

1. Сделай файл `content/lessons/<id>.json`. `id` пишется латиницей через дефис, например `lesson-03-fractions`.
2. Делай 8–15 вопросов **строго по конспекту**, смешивая типы. Сложность нарастает от простого к сложному. Каждому вопросу ставь `topic`: короткую подтему урока (3–6 разных тем на урок). Из них строится радар-диаграмма. В `explain` коротко объясни, почему ответ такой.
3. Сделай переводы `<id>.uz.json` и `<id>.en.json` (см. «Переводы»). Проверь: `npm run check`.
4. Сделай commit и push в рабочую ветку. Render сам передеплоит, и тест появится у учителя во вкладке «Тесты» как **черновик**. Ученики его не видят, пока учитель не нажмёт «Отправить» и не выберет группу.

Если урок уже решали ученики, вопросы при импорте из `content/` не перезаписываются. Чтобы поменять такой урок, сделай новый `id`.

### Нумерация, доступ и скрытые тесты

- В уроке можно поставить `"order": N` (номер урока): по нему тесты идут в списке учителя по порядку. У готовых тестов (`exam`) ставь большой номер (100).
- Учитель сам даёт доступ к тесту: «Ученики» в карточке теста → выбирает одного или многих (или группу целиком) → «Дать доступ» (`POST /api/admin/grant`). Кнопка «Отправить» (группе) осталась как была.
- **Путь ученика** — один «Курс» из всех уроков с `order` (1–26). Открытые — обычные узлы, остальные закрыты замком (`/api/me` → `locked`). Личные задания от Claude (`personal`) идут отдельным блоком «Личные задания».
- Учитель: «Тесты» → «Выдать доступ ученикам» → выбирает учеников (одного, нескольких, группу, всех) → выбирает тесты (можно «с 1 по N») → «Дать доступ» (`POST /api/admin/grant-many {userIds, lessonIds, noLearn}`). Уже открытый тест второй раз не выдаётся.
- Миграция `access-v1` (один раз при старте, лог `[access-migrate]`): каждому, у кого был доступ к уроку N, открываются все уроки 1…N. Они помечены `noXp` — повторное решение очков не даёт (и за обучалку 0).
- Карточки уроков курса (с `order` < 100, не `personal`) учителю в «Тесты» **не показываются** (`course: true` в `adminOverview`); доступ к ним только через «Выдать доступ ученикам». Готовые тесты (`exam`) и прочее показываются как раньше. Новый урок с `order` попадает на Путь учеников закрытым.
- Страница группы → «Тесты» / «Статистика» показывают уроки по всем доступам учеников группы: отправленные группе И выданные лично через «Выдать доступ» (`groupLessons` в `logic.js`, `GET /api/admin/groups/:gid/lessons/:lid/attempts`).
- У учителя есть своя вкладка «Путь» (`tabTeacherPath`): тот же вид, что у учеников, но все уроки открыты; нажатие запускает обучалку или тест в режиме превью (без очков).
- Обучалка на Пути называется «Обучалка N урока» (`learnName`, перевод шаблоном в `PATTERNS`). Закрытый урок показывает только замок: обучалка открывается вместе с доступом, тест после неё.
- Уроки 3 (`lesson-03-selectors`) и 6–9 (`lesson-06-flexbox`, `lesson-07-flex-practice`, `lesson-08-grid`, `lesson-09-responsive`) уже в курсе. Старый «Уроки 1–3» скрыт и без `order` (`"order": null` в json сбрасывает номер). Миграция `access-v2` открыла урок 3 (без очков) всем, у кого был доступ к уроку 3 и выше или к старому «Уроки 1–3».
- `content/archive.json`: список id тестов, которые один раз скрываются из списка учителя (ученики и результаты не трогаются). Учитель возвращает их кнопкой «Скрытые тесты» внизу вкладки.
- Много уроков сразу удобно собирать скриптом-генератором, где каждый текст пишется тройкой (ru, uz, en): так структура переводов всегда совпадает.

### Готовый тест (без конспекта)

Если учитель присылает готовый тест (контрольную, итоговый тест), а не конспект, сделай урок с `"kind": "exam"` и id вида `exam-<что-то>`: только `questions`, без `learn`. Вопросы и правильные ответы бери из теста учителя как есть, `explain` — из его пояснений. Переводы uz/en тоже нужны. На «Пути» у учеников такой тест выглядит как отдельный кружок «Итоговый тест», у учителя в «Тестах» он помечен «тест без обучалки» и отправляется так же: группе или одному ученику.

### Переводы (обязательно для каждого урока)

Ученик выбирает язык (ru, uz, en), и тест с обучалкой показываются на нём. Поэтому к каждому уроку `<id>.json` (основной, на русском) делай ещё два файла рядом: `<id>.uz.json` и `<id>.en.json`. В них поля `title`, `description`, `questions`, `learn`, переведённые целиком: вопросы, варианты, `explain`, `topic`, слайды, строки внутри `code` (если это текст для вывода).

- Структура должна совпадать с оригиналом: столько же вопросов и разделов, те же `type`, у `choice` тот же `answer` и столько же `options`, у `truefalse` тот же `answer`, у `match` столько же пар. `npm run check` это проверяет.
- Если перевода нет, ученик видит русский вариант.
- Переводы применяются и к урокам, которые уже решали: их можно дописывать без нового `id`.

### Обучалка (обязательно для каждого конспекта)

У каждого урока, кроме теста, есть **обучалка** (`learn`). Ученик сначала проходит её, и только потом открывается тест. В обучалке маскот в очках и с палочкой объясняет тему по разделам конспекта. После каждого раздела он говорит «Теперь проверим, чему ты научился за эту секцию!» и задаёт 1–3 вопроса.

- Раздел обучалки соответствует разделу конспекта (1, 2, 3…). В разделе 2–5 слайдов, в каждом слайде одна мысль простыми словами.
- `text` слайда понимает разметку `**жирный**`, `` `код` `` и `\n`. `code` — блок кода под репликой. `emoji` — большая 3D-картинка над репликой.
- `"quote": true` оформляет реплику как «**Учитель Азиз говорил:** «…»». Сюда пиши главные правила из конспекта. `{teacher}` в любом тексте заменяется на имя учителя.
- В `check` идут вопросы того же формата, что в тесте. Они проверяют только этот раздел и не повторяют вопросы теста дословно.

```json
"learn": {
  "intro": "Привет! Сегодня повторяем … Поехали!",
  "sections": [
    { "title": "if / else",
      "slides": [ { "emoji": "🧠", "text": "…" }, { "text": "…", "code": "…" }, { "quote": true, "text": "главное правило" } ],
      "check": [ { "type": "truefalse", "topic": "if / else", "prompt": "…", "answer": false, "explain": "…" } ] }
  ]
}
```

### Результаты учеников и личные задания

У Claude нет прямого доступа к базе. Результаты он читает в **логах Render** (сервис `srv-dbh3oicipgvc73dmrjfg`, workspace `tea-d9kukvdaeets73a8h3e0`) через `list_logs` с фильтром `text`:
- `[result]` пишется после каждого теста: ученик, процент, ошибки (`prompt`, что ответил `given`, что правильно `right`).
- `[learn]` пишется после обучалки: ответы на проверки разделов.
- `[report]` пишется, когда учитель жмёт «Отправить отчёт Claude» во вкладке «Бот». Одна строка на ученика: оценки, пройденные обучалки, все неисправленные ошибки. В конце строка `[report-end]`.

Когда учитель просит сделать личные задания, прочитай `[report]` и для каждого ученика с ошибками сделай файл `content/lessons/personal-<userId>-<тема>.json` с полем `"personal": ["<userId>"]`. Такой урок сразу назначается только этому ученику, а бот присылает ему уведомление. Обучалка в нём разбирает **именно его ошибки**: «Ты ответил X, а правильно Y, потому что…». Тест к нему делай коротким, на 5–8 вопросов по тем же темам.

Деплой: в Render не работает автодеплой с GitHub. После push запусти `trigger_deploy` для сервиса.

### Формат урока

```json
{
  "id": "lesson-03-fractions",
  "title": "Дроби: сложение",
  "emoji": "🧮",
  "description": "Одна строка о чём урок",
  "questions": [
    { "type": "choice", "topic": "Тема", "prompt": "Вопрос?", "options": ["A", "B", "C", "D"], "answer": 1, "explain": "…" },
    { "type": "truefalse", "topic": "Тема", "prompt": "Утверждение", "answer": true },
    { "type": "fill", "topic": "Тема", "prompt": "Вставь пропущенное", "text": "display: ___;", "answer": ["flex"], "extra": ["block", "grid", "none"] },
    { "type": "order", "topic": "Тема", "prompt": "Собери …", "tokens": ["в", "правильном", "порядке"], "extra": ["лишнее"] },
    { "type": "match", "topic": "Тема", "prompt": "Соедини пары", "pairs": [["термин", "определение"], ["…", "…"]] }
  ]
}
```

Необязательные поля вопроса: `hint` (подсказка), `code` (блок кода под вопросом).

- **Тип `input` (ученик сам печатает ответ) учитель попросил не использовать.** Вместо него `fill`: в `text` стоят пропуски `___`, ученик нажимает плитки из набора (`answer` по порядку пропусков + лишние `extra`, 3 штуки хватит). Число `___` = длине `answer`. Сравнение без учёта регистра.
- Все старые `input` заменены на `fill`. Чтобы поменять вопросы урока, который уже решали, не меняя `id`, подними в нём `"qrev"` (число): сервер заменит вопросы, если их столько же и порядок тот же (лог `[qrev]`).

## Устройство

- `src/server.js`: Express API и бот (webhook, если есть публичный https-URL, иначе long polling). Напоминания проверяются каждые 30 секунд.
- `src/logic.js`: вся предметная логика: группы, публикации, попытки, XP, комбо, серии, статистика.
  - «Работа над ошибками»: у каждого ученика копилка вопросов, на которые его последний ответ был неверным (`mistakesOf`). Из неё собирается личный тест до 10 вопросов (`POST /api/attempts {mistakes:true}`). Если ученик отвечает верно, вопрос уходит из копилки.
- `src/bot.js`: команды `/start`, `/link` (привязать чат Telegram-группы к группе курса), `/stop`, уведомления о тестах, напоминания.
- `src/store.js`: всё состояние в одном JSON-документе. В продакшене он лежит в Postgres (`DATABASE_URL`), локально в `data/state.json`.
- `public/`: Mini App без сборки (vanilla JS), графики на SVG.
  - `mascots.js`: 11 маскотов-напарников (mimi, kapi, dino, axi, boo, ano, zip, ugo, fox, bot, plu — Шарки, акулёнок учителя: готовые картинки в `public/m/plu/<эмоция>.webp`, рисунок не меняем, `RASTER` в `mascots.js`) × 11 поз (happy, cheer, oops, sad, think, wow, love, sleepy, peace, talk, teach), рисуются SVG-кодом. В позах `talk` и `teach` двигается рот (CSS), а класс `quiet` его останавливает. В `teach` у маскота очки и волшебная палочка.
  - `mascot-info.js`: досье каждого маскота (6 фактов на ru/uz/en и 5 характеристик). Выбор напарника: в «Внешнем виде» одна карточка и кнопка «Выбрать другого», она открывает полноэкранный выбор в стиле рилсов (`mascotReels` в `app.js`): свайп снизу вверх, справа кнопки-факты, по нажатию сбоку выезжает облачко с досье. Новый маскот = тело в `mascots.js` + запись в `MASCOT_IDS` (`logic.js`) + досье + имя в `PHRASES` + цена в `MASCOT_PRICES` и еда в `FOODS` (`shop.js`) + картинки для бота (`scripts/render-mascots.js`). Персонажей рисуем своих, чужих (Sonic, Zootopia и т. п.) не копируем.
  - `i18n.js`: языки интерфейса ru, uz, en. Интерфейс пишется по-русски, переводчик подменяет надписи на лету по словарю `PHRASES` и шаблонам (`PATTERNS`, `TOKENS`, `NOUNS`). **Новую строку интерфейса добавляй в `PHRASES` сразу с переводами.** Контент уроков не переводится. Язык ученика хранится в `prefs.lang`, на нём же бот пишет в личку.
  - `icons.js`: иконки интерфейса Solar (bold-duotone). Новые иконки берутся из `@iconify-json/solar`.
  - `e/`: 3D-эмодзи Microsoft Fluent Emoji (MIT, `e/LICENSE.txt`; `<код>.webp` + `index.json`), `ea/`: анимированные. Любой эмодзи в `emoji` урока или группы рисуется в 3D, а системные смайлики в любом тексте интерфейса (кнопки, плашки, тосты, реплики маскота) сами заменяются на 3D (`startEmojify` в `app.js`; не трогает поля ввода, код, `<select>` и `[data-noemoji]`). В сообщениях бота в Telegram смайлики рисует сам Telegram.
  - Ученик сам выбирает напарника, цвет (lime, sakura, lavender, ocean, peach, mint), тему (auto, light, dark) и язык (ru, uz, en), всё это хранится в `user.prefs`.

## Журнал, оценки и дневник

`src/journal.js`: расписание групп (`group.schedule`), занятия с посещаемостью (`S.classes`; не путать с `S.sessions` — это входы на сайт) и оценки (`S.grades`). Время — Ташкент (`TZ_OFFSET_MIN=300`).
- Учитель задаёт время уроков: страница группы → «Время для журнала» или «Журнал» → группа → «Время» (день недели, начало–конец). В «Журнале» сверху кнопки групп; у выбранной группы — ученики с плюсами (был), минусами (не был), последними оценками и средним баллом. Через 10 минут после начала урока (`ATTEND_ASK_AFTER_MIN`) бот пишет учителю «Кого нет?» с кнопками-учениками. Учитель отвечает именами текстом («Бегзод, Наргиза», можно латиницей/сокращённо) или кнопками, «Все пришли» — никого нет. Лог `[attendance-ask]`, `[attendance]`.
- Личное время ученика (если он занимается не со всей группой): `user.schedule`, `setUserSchedule`; `user.showTzMin` — часовой пояс, в котором ему показывать время в дневнике (180 = Москва). Время по просьбе учителя Claude пишет в `content/schedule.json` (`{ id, groups: [{ match, slots }], students: [{ userId | username, slots, tzMin? }] }`), каждый `id` применяется один раз при старте (лог `[schedule]`).
- Отсутствующему (и его родителям) бот пишет «почему не пришёл?»; ответ ученика сохраняется (`reasons`) и пересылается учителю.
- Оценка 1–10 (страница ученика → «Оценка» или «Журнал» → «Поставить оценку»): `xp = балл × 20` (10 = 200 XP), идёт в общую лигу и лигу группы (через `bonusXp`). Тема (урок) и комментарий необязательны. Лог `[grade]`. Ученик получает сообщение; при оценке ≤ 5 — с подбадриванием и предложением повторить тему.
- «Журнал» у учителя: календарь месяца (зелёный — все были, красный — пропуски, жёлтый — ждёт отметки, ★ — оценки), день → занятия (нажми ученика, чтобы исправить), «Отметить урок» вручную.
- «Дневник» у ученика (и у учителя/родителя на странице ученика): календарь (зелёный — был, красный — не был, цифра — оценка), посещаемость, средний балл, следующий урок. Маскот подбадривает после низкой оценки и предлагает «Повторить тему».
- API: `GET /api/me/diary`, `GET /api/admin/journal`, `POST /api/admin/groups/:gid/schedule {slots}`, `POST /api/admin/groups/:gid/sessions`, `POST /api/admin/sessions/:sid {absent}`, `POST /api/admin/grades {userId, value, lessonId?, comment?, date?}`, `DELETE` для занятий и оценок.

## Напоминалки (3 раза в день)

`src/nudge.js`: в 06:30, 13:00 и 20:00 (`NUDGE_TIMES`, время Ташкента; у ученика с `showTzMin` — его пояс) бот пишет ученикам и родителям. Выключить: `NUDGES=0`. Лог `[nudge]`.
- Ученик с нерешёнными тестами (`logic.testStatus`; уроки, открытые миграцией `auto`, долгом не считаются): «Пора решать тест N, но ты ещё не решил …» — каждый слот, пока не решит. Решил тест, о котором напоминали, — сутки приходит «Тему не забыл? Брось себе вызов — пройди ещё раз», потом тишина.
- Родитель (у кого выбраны дети): первый раз «учитель дал тест, проверьте, решён ли», дальше «всё ещё не решил», после решения «✅ решил, N%»; вечером — был ли ребёнок сегодня на уроке и оценка за день.
- К сообщению прикладывается картинка маскота ученика: `public/m/tg/<маскот>-<поза>.jpg`. Их рендерит `scripts/render-mascots.js` (нужны запущенный сервер и Playwright) — перезапускай после смены рисунка или добавления маскота.
- У родителя на «Главной» — календарь каждого ребёнка (`mountKidDiaries`): был / не был, оценки, посещаемость, средний балл.

## Магазин (за XP)

`src/shop.js`. Баланс = заработанный XP − потраченный (`S.purchases`); лига считает заработанный XP, покупки её не уменьшают. Вкладка ученика «Магазин» (`tabShop`). Лог `[shop]`, `[magnifier]`, `[potion]`.
- **Маскоты**: бесплатные только `kapi` и `dino`, остальные покупаются (`MASCOT_PRICES`, Шарки — 600). Купленные — `user.owned`. Кто выбрал маскота до магазина, получил его бесплатно (миграция `shop-v1`). В профиле чужие маскоты под замком, нажатие ведёт в магазин; сервер не даст выбрать некупленного.
- **Еда** (`FOODS`): у каждого маскота своя (дино — мясо, Бу — «Душа» 👻, Шарки — кальмар…). Покупка = покормить. Чужую еду маскот не ест: «Ты что? Лучше реши тест, а? Дурачок 😜».
- **Состояние маскота** (`shop.pet`, за 7 дней): `hungry` — ни теста, ни еды сегодня к вечеру или вчера весь день (худеет, слабеет, бледнеет); `fat` — кормили ≥3 раз и больше, чем решали (толстенький); `strong` — решил ≥3 тестов и почти не кормил (бицепсы, пресс). Рисуется у любого маскота: `mascot(id, emo, size, cls, crop, cond)` в `mascots.js`, анимации `cond-*` в `app.css`.
- **Лупа** (100 XP, раз за тест): маскот на 30 секунд показывает раздел обучалки по теме вопроса (`POST /api/attempts/:id/magnifier {index}`).
- **Зелье** (150 XP, покупается заранее, `user.potions`; одно за тест): короткая подсказка (`hint` вопроса или правило раздела) и у «выбора» убирает один неверный вариант (`POST /api/attempts/:id/potion {index, options}`).
- Напоминалки: в сообщении о долгах маскот говорит, что проголодался («реши тест или покорми меня»). Покормил после напоминания — следующее ученику пропускается, родителям в этот день про долги не пишем. Картинки состояний: `public/m/tg/<маскот>-hungry|fat|strong.jpg`.

## Бонусные баллы

Если учитель просит начислить кому-то баллы, допиши запись в `content/bonuses.json`: `{ "id": "<дата>-<кто>", "login": "<почта/логин с сайта>" или "userId": "<ID>", "xp": 85, "reason": "…" }`. Каждый `id` начисляется один раз при запуске сервера (лог `[bonus]`), отрицательный `xp` снимает баллы. Бонусы идут в общую лигу и лигу группы. Учитель может сделать то же сам: страница ученика → «Начислить баллы».

## Родители

Новый пользователь при `/start` (или при первом входе в приложение) выбирает роль: ученик или родитель (`user.needRole` → `user.role`). Тех, кто был раньше, это не касается, они остаются учениками. У родителя своё приложение: «Главная» с его детьми (`user.children`, выбирает сам) и фразами маскота, «Лига» (общая и группы детей), «Ученики» (прогресс любого ученика курса, как у учителя), «Профиль». Родители не попадают в списки учеников, лиги и отчёты. API: `/api/me/role`, `/api/parent/*`.

## Сайт (без Telegram)

Тот же Mini App открывается в обычном браузере. Если его открыли не из Telegram, показывается экран входа по почте и паролю (`POST /api/auth/login`, дальше заголовок `X-Session`). Учётные записи задаются переменной `SEED_ACCOUNTS="почта:пароль:Имя;…"` на сервере, пароли хранятся только в виде хеша scrypt. Ученики с сайта получают ID вида `w…`, в остальном всё то же: группы, тесты, обучалки, лига.

- Ученики из Telegram входят на сайт в **свой же** аккаунт: учитель жмёт «Создать входы ученикам» во вкладке «Бот» (`POST /api/admin/logins`), и каждый получает от бота логин (имя латиницей + 4 цифры ID) и пароль. Новый пароль одному ученику — на его странице или командой бота `/site`. Пароли хранятся только хешем, учитель видит их один раз. Ссылка в сообщении берётся из `SITE_URL` (если не задан, из `PUBLIC_URL`).
- Сайт хостится на **Vercel**: `vercel.json` раздаёт `public/` как статику, а `/api/*` пересылает на сервер с ботом (Render). Данные у сайта и бота общие.
- База: Postgres. Чтобы переехать на **Supabase**, достаточно положить в `DATABASE_URL` строку подключения Supabase (Session pooler, порт 5432). SSL включится сам.

Локальный запуск без Telegram: `npm run dev`, потом открыть `http://localhost:3000/?dev=7183098167` (учитель) или `?dev=111&name=Ученик`.

Переменные окружения: `BOT_TOKEN`, `TEACHER_NAME` (имя в фразах «Учитель … говорил», сейчас «Азиз»), `DATABASE_URL`, `ADMIN_IDS`, `PUBLIC_URL` (на Render берётся `RENDER_EXTERNAL_URL`), `ADMIN_TOKEN` (опционально, Bearer-доступ к `/api/admin/*`), `APP_LINK` (ссылка для кнопки в группах, по умолчанию `https://t.me/<bot>?start=play`).
